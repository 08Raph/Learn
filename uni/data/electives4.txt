#LESSON Floating-point numbers and error | 12
Computers cannot store most real numbers exactly. **Numerical methods** are algorithms that compute approximate answers to mathematical problems, together with an understanding of how wrong those answers might be.

### Floating point
A floating-point number is stored in scientific notation in base 2: a **sign**, a **significand** of fixed length and an **exponent**. The usual 64-bit "double" has 53 bits of significand, about **15 to 17 significant decimal digits**.

Two consequences:

- Most decimal fractions cannot be represented exactly. One tenth is a repeating fraction in binary, as one third is in decimal.

```js
0.1 + 0.2            // 0.30000000000000004
0.1 + 0.2 === 0.3    // false
```

- The gaps between representable numbers grow with magnitude. Near 1 the spacing is about 2.2 × 10⁻¹⁶ (**machine epsilon**); near 10¹⁶ it is 2, so adding 1 changes nothing.

Never test floating-point numbers for exact equality. Compare with a tolerance: `Math.abs(a - b) < 1e-9`, or a relative tolerance when magnitudes vary.

### Kinds of error
- **Rounding error:** from the finite precision of each operation.
- **Truncation error:** from replacing an infinite process with a finite one, such as stopping a series after ten terms.
- **Error in the data:** the inputs were measurements.

Measure error as:

```text
absolute error = |approximate − exact|
relative error = |approximate − exact| / |exact|
```

Relative error is usually the meaningful one. An error of 1 metre is negligible in the distance to the Moon and enormous in the width of a door.

### Catastrophic cancellation
Subtracting two nearly equal numbers destroys significant digits. If a and b agree to twelve digits and each is accurate to sixteen, their difference is accurate to about four.

The quadratic formula shows it. When b² is much larger than 4ac, one root computes `−b + √(b² − 4ac)`: a subtraction of nearly equal quantities. The cure is to compute the well-behaved root first and obtain the other from the product of the roots, c/a. Rearranging a formula to avoid subtracting close values is the commonest numerical repair.

### Accumulation
Adding many numbers accumulates rounding error, and the order matters: adding small numbers to a large running total loses them. Summing from smallest to largest helps, and **compensated (Kahan) summation** carries the lost low-order part forward.

### Conditioning and stability
Two different things can make an answer inaccurate:

- A problem is **ill-conditioned** if small changes in its input cause large changes in its answer. No algorithm can rescue it; the difficulty is in the problem.
- An algorithm is **unstable** if it magnifies rounding errors even on a well-conditioned problem. A different algorithm fixes that.

### Overflow and special values
Results too large become `Infinity`; undefined operations such as 0/0 give `NaN` ("not a number"), which is not equal to anything, including itself. A NaN in an output means something went wrong earlier and propagated silently.

### Money
Never hold money in binary floating point. Use whole numbers of the smallest unit (cents) or a decimal type.

> Key idea: Floating-point numbers carry about sixteen digits and are almost never exact. Compare with tolerances, measure relative error, and avoid subtracting nearly equal values.

#LESSON Finding roots of equations | 12
Many problems reduce to solving f(x) = 0: when does the projectile land, what interest rate makes the payments balance. Most such equations have no formula for the answer. **Root-finding** methods produce a sequence of better and better approximations.

### Bisection
If f is continuous and f(a) and f(b) have **opposite signs**, there is a root between them. Bisection halves the interval repeatedly:

```text
repeat:
    m = (a + b) / 2
    if f(a) and f(m) have opposite signs:  b = m
    otherwise:                             a = m
until b − a is small enough
```

Each step halves the uncertainty, gaining one binary digit. After n steps the interval is (b − a)/2ⁿ. Bisection is slow, but it **cannot fail** once a sign change is bracketed. Reaching ten decimal digits takes about 33 steps.

### Newton's method
Use the slope. From a guess x, follow the tangent line to where it crosses zero:

```text
x_next = x − f(x) / f'(x)
```

Near a root, Newton's method converges **quadratically**: the number of correct digits roughly doubles at every step. Five or six steps typically reach full machine precision.

Its weaknesses:

- It needs the derivative f'.
- It needs a starting point reasonably close to the root. From a poor start it can diverge or jump to a different root.
- It fails where f'(x) is zero or tiny.

Computing a square root is the classic example. For f(x) = x² − a, Newton's step simplifies to `x = (x + a/x) / 2`, a method known for four thousand years.

### The secant method
When the derivative is unavailable, estimate the slope from the last two points:

```text
x_next = x1 − f(x1) × (x1 − x0) / (f(x1) − f(x0))
```

It converges a little more slowly than Newton and needs no derivative.

### Combining them
Production root-finders are **hybrids**. Brent's method takes fast secant-like steps when they behave and falls back on bisection when they do not, keeping the root bracketed throughout. It is safe and fast, and it is what library functions use.

### When to stop
An iteration never reaches the exact answer. Stop when:

- successive estimates differ by less than a tolerance, or
- |f(x)| is below a tolerance, and
- always, when a **maximum number of iterations** is reached. A loop with no limit will one day hang.

A tolerance tighter than the precision of floating point can never be met.

### Rate of convergence
| Method | Convergence | Needs | Reliability |
|---|---|---|---|
| Bisection | Linear: one bit per step | A sign change | Always works |
| Secant | Superlinear | Two starting points | May fail |
| Newton | Quadratic | Derivative and a good start | May fail |

### Fixed-point iteration
Some equations can be rearranged as x = g(x) and solved by repeating x ← g(x). It converges when the slope of g near the solution is less than 1 in size. Many iterative algorithms, including those used to train models, are of this form.

> Key idea: Bisection is slow and certain; Newton's method is fast and fragile. Robust solvers bracket the root and use fast steps only when they stay inside the bracket.

#LESSON Numerical differentiation and integration | 12
### Differentiation
The derivative is the limit of (f(x + h) − f(x))/h as h tends to zero. A computer cannot take a limit, so it uses a small h.

```text
forward difference:   f'(x) ≈ (f(x + h) − f(x)) / h              error ∝ h
central difference:   f'(x) ≈ (f(x + h) − f(x − h)) / (2h)       error ∝ h²
```

The central difference is far more accurate for the same h: halving h divides its error by four, not two.

### The step-size dilemma
Smaller h reduces the truncation error. But the numerator subtracts two nearly equal numbers, and that cancellation error **grows** as h shrinks. The total error falls and then rises again. For a central difference in double precision the best h is around 10⁻⁵ relative to the size of x. Choosing h = 10⁻¹⁵ gives nonsense.

Numerical differentiation is therefore inherently delicate. Where derivatives are needed to full accuracy, as in training neural networks, they are computed by **automatic differentiation**, which applies the chain rule exactly to each operation of the program.

### Integration
The integral of f from a to b is the area under its curve. When there is no formula, or f is known only at measured points, approximate the area with simple shapes. Divide [a, b] into n strips of width h = (b − a)/n.

**The trapezoid rule** joins neighbouring points with straight lines:

```text
∫ f ≈ h × [ f(x0)/2 + f(x1) + f(x2) + … + f(x(n−1)) + f(xn)/2 ]
```

Its error is proportional to h²: doubling the number of strips divides the error by four.

**Simpson's rule** fits a parabola through each pair of strips (n must be even):

```text
∫ f ≈ (h/3) × [ f(x0) + 4f(x1) + 2f(x2) + 4f(x3) + … + 4f(x(n−1)) + f(xn) ]
```

Its error is proportional to h⁴: doubling n divides the error by sixteen. It is **exact for polynomials up to degree three**, which is a useful test of an implementation.

### Estimating the error
You rarely know the true answer. Compute with n strips and again with 2n: the difference between the two results estimates the error. **Adaptive** methods do this automatically, using narrow strips only where the function changes quickly.

### Harder integrals
- **Gaussian quadrature** chooses the sample points cleverly and reaches high accuracy with very few evaluations of a smooth function.
- In many dimensions, grids become impossibly large: ten points per axis in twenty dimensions is 10²⁰ points. **Monte Carlo integration** samples random points instead. Its error falls as 1/√N whatever the dimension, which is why it dominates in finance, physics and graphics.

### Integration smooths, differentiation roughens
Integration averages out noise in data; differentiation amplifies it. Differentiating measured data needs smoothing first. This asymmetry is worth remembering whenever you process signals.

> Key idea: Approximate derivatives with central differences and a sensible step, and integrals with the trapezoid or Simpson's rule. Estimate the error by refining and comparing.

#LESSON Linear systems and differential equations | 13
### Systems of linear equations
Circuits, structures, graphics, statistics and machine learning all lead to solving **Ax = b**: many linear equations in many unknowns.

**Gaussian elimination** reduces the system to triangular form by subtracting multiples of one equation from the others, then solves it from the bottom up (**back substitution**). For n unknowns it takes about n³/3 operations.

### Pivoting
Elimination divides by the **pivot**, the diagonal entry. If the pivot is zero, it fails; if it is tiny, rounding errors are magnified enormously. **Partial pivoting** swaps rows so that the largest available entry in the column becomes the pivot. It costs almost nothing and makes the method stable in practice. Elimination without pivoting is a bug waiting to happen.

### Do not compute the inverse
The formula x = A⁻¹b is correct mathematics and poor computing. Forming the inverse takes more work and loses more accuracy than solving the system directly. To solve with many right-hand sides, factorise A once (**LU decomposition**) and reuse the factors.

### Conditioning
The **condition number** of A measures how much errors in b can be amplified in x. With a condition number of 10⁸ you lose about eight of your sixteen digits. Nearly parallel equations give ill-conditioned systems, and no algorithm removes that; it is a property of the problem.

### Large and sparse systems
Real systems may have millions of unknowns, with almost all coefficients zero. Elimination would fill in the zeros and exhaust memory. **Iterative methods** (Jacobi, Gauss-Seidel, conjugate gradient) start from a guess and improve it using only multiplications by A, stopping when the residual Ax − b is small enough.

### Ordinary differential equations
A differential equation gives the **rate of change** of a quantity: y' = f(t, y), with a known starting value. Motion, population growth, chemical reactions and circuits are described this way. Few have formula solutions, so we step forward in time.

**Euler's method** follows the slope for a short step h:

```text
y_next = y + h × f(t, y)
t_next = t + h
```

Simple and inaccurate: the total error is proportional to h, so ten times the accuracy costs ten times the work. It also drifts systematically, for example by steadily adding energy to a simulated orbit.

**Runge-Kutta methods** sample the slope at several points within the step and combine them. The classical fourth-order method (RK4) uses four evaluations per step and has error proportional to h⁴: halving the step divides the error by sixteen. It is the workhorse for ordinary problems.

### Stability and stiffness
With too large a step, a numerical solution can oscillate and blow up even though the true solution decays quietly. The step must be below a limit that depends on the equation. **Stiff** equations, with processes on very different time scales, force explicit methods to take absurdly small steps; **implicit** methods, which solve an equation at each step, remain stable with large ones.

**Adaptive** solvers estimate the error at each step and adjust h automatically.

### Use libraries, understand them
Do not write your own linear solver or integrator for real work. Mature libraries (LAPACK, and the numerical packages of every scientific language) are fast, tested and careful about edge cases. This course lets you choose the right routine, set its tolerances sensibly, and recognise when its answer cannot be trusted.

> Key idea: Solve linear systems by elimination with pivoting, never by inverting. Step differential equations with a method whose order and stability suit the problem.

#LESSON Interpolation and curve fitting | 12
### Filling in between known values
A sensor reports a temperature every minute; an animation has keyframes at a few moments; a table lists a function at a few points. **Interpolation** builds a function that passes exactly through the known points and estimates the values between them.

### Linear interpolation
The simplest method joins neighbouring points with straight lines. Between (x0, y0) and (x1, y1):

```text
y = y0 + (x − x0) · (y1 − y0) / (x1 − x0)
```

Graphics and games call this **lerp**, written as a + t·(b − a) for t from 0 to 1. It is fast and never overshoots, but the result has corners at every data point.

### Polynomial interpolation
Through n + 1 points with different x values there is exactly one polynomial of degree at most n. **Lagrange's formula** writes it directly as a weighted sum of the y values. It is smooth and exact at the points.

But high-degree polynomials behave badly. With many equally spaced points, the curve can swing wildly between them near the ends of the range. This is **Runge's phenomenon**, and it is why fitting a degree-20 polynomial through 21 points is almost never the right idea.

### Splines
A **spline** joins many low-degree pieces, usually cubics, so that the curve and its first and second derivatives match where the pieces meet. The result is smooth without the wild swings of one big polynomial. Fonts, vector drawing tools (Bézier curves are close relatives), animation paths and CAD software all use splines.

### Interpolation versus fitting
Interpolation insists on passing through every point. That is right when the data are exact, like values from a formula. Measurements contain noise, and forcing a curve through every noisy point fits the noise. Then you **fit** instead: choose a simple model and minimise the overall error, as least squares does, accepting that the curve misses individual points.

### Extrapolation
Using the curve **outside** the range of the data is extrapolation, and it is risky. A polynomial that fits well inside the range can head off in any direction outside it. Treat extrapolated values as guesses and say so.

> Key idea: Interpolation passes exactly through known points: linear for speed, splines for smoothness, and high-degree polynomials rarely. With noisy data, fit a simple model instead, and be wary of extrapolating.

#LESSON Optimisation and Monte Carlo methods | 13
### Finding the lowest point
Much of computing is **optimisation**: choose inputs that make some cost as small as possible. Training a machine-learning model minimises a loss; a route planner minimises travel time; a compiler's register allocator minimises spills.

### Gradient descent
If the cost f depends on numbers x, its **gradient** points in the direction of steepest increase. So step the other way:

```text
x_new = x − η · ∇f(x)
```

The **step size** (learning rate) η matters. Too small and progress is painfully slow; too large and the steps overshoot, bounce around or diverge. If the gradient has no formula, it can be estimated with the finite differences from an earlier lesson.

Gradient descent finds a **local minimum**, a point lower than its neighbours, which need not be the lowest point overall. Starting from several random points, or adding momentum, helps on bumpy landscapes.

### Newton's method for minimisation
Newton's method for roots can be applied to the derivative: a minimum is where f'(x) = 0. Using the second derivative as well, it takes much larger, well-aimed steps and converges very fast near the answer, but each step costs more and it can head for a maximum instead. Practical optimisers combine ideas from both.

### Monte Carlo: answers from randomness
Some quantities are hard to compute directly but easy to **sample**. Monte Carlo methods estimate them with random numbers.

Estimating π: pick random points in the square from (0, 0) to (1, 1). The fraction landing inside the quarter circle x² + y² ≤ 1 approaches π/4, so four times that fraction approaches π.

Integration works the same way: the average of f at many random points, times the length of the interval, estimates the integral. This is the method of choice in many dimensions, where grid-based rules need impossibly many points.

### How accurate is it?
The error of a Monte Carlo estimate shrinks like **1 / √N** for N samples. Ten times the accuracy costs a hundred times the samples. Reporting the estimate with its standard error is part of doing it honestly.

### Reproducibility
Computer random numbers are **pseudo-random**: a generator started from the same **seed** produces the same sequence. Fix and record the seed when results must be repeatable, as in tests and scientific work. Use a cryptographically secure generator, not Math.random, for anything security-related.

> Key idea: Gradient descent steps against the gradient and finds local minima, with the step size deciding speed and stability. Monte Carlo methods estimate hard quantities by random sampling, with error falling like 1/√N.

@solution
function r6(x) {
  return Math.round(x * 1000000) / 1000000;
}

function relError(approx, exact) {
  return r6(Math.abs(approx - exact) / Math.abs(exact));
}

function bisect(f, lo, hi, tol) {
  let a = lo, b = hi, guard = 0;
  while (b - a > tol && guard < 200) {
    const m = (a + b) / 2;
    if (f(a) * f(m) <= 0) { b = m; } else { a = m; }
    guard++;
  }
  return Math.round((a + b) / 2 * 10000) / 10000;
}

function newton(f, df, x0, steps) {
  let x = x0;
  for (let i = 0; i < steps; i++) {
    x = x - f(x) / df(x);
  }
  return r6(x);
}

function derivative(f, x, h) {
  return r6((f(x + h) - f(x - h)) / (2 * h));
}

function trapezoid(f, a, b, n) {
  const h = (b - a) / n;
  let sum = (f(a) + f(b)) / 2;
  for (let i = 1; i < n; i++) {
    sum += f(a + i * h);
  }
  return r6(sum * h);
}

function simpson(f, a, b, n) {
  const h = (b - a) / n;
  let sum = f(a) + f(b);
  for (let i = 1; i < n; i++) {
    sum += (i % 2 === 1 ? 4 : 2) * f(a + i * h);
  }
  return r6(sum * h / 3);
}

function euler(f, y0, t0, t1, n) {
  const h = (t1 - t0) / n;
  let y = y0, t = t0;
  for (let i = 0; i < n; i++) {
    y = y + h * f(t, y);
    t = t + h;
  }
  return r6(y);
}

function solve(A, b) {
  const n = A.length;
  const M = A.map((row, i) => row.concat([b[i]]));
  for (let col = 0; col < n; col++) {
    let best = col;
    for (let r = col + 1; r < n; r++) {
      if (Math.abs(M[r][col]) > Math.abs(M[best][col])) { best = r; }
    }
    if (Math.abs(M[best][col]) < 1e-12) return null;
    const tmp = M[col]; M[col] = M[best]; M[best] = tmp;
    for (let r = col + 1; r < n; r++) {
      const k = M[r][col] / M[col][col];
      for (let c = col; c <= n; c++) {
        M[r][c] -= k * M[col][c];
      }
    }
  }
  const x = new Array(n).fill(0);
  for (let r = n - 1; r >= 0; r--) {
    let s = M[r][n];
    for (let c = r + 1; c < n; c++) {
      s -= M[r][c] * x[c];
    }
    x[r] = s / M[r][r];
  }
  return x.map((v) => r6(v) + 0);
}

#LESSON Limits and the derivative | 12
**Calculus** is the mathematics of change. It answers two questions: how fast is something changing at this instant, and how much has accumulated in total? This course covers both, with an eye to their use in computing: optimisation, simulation, graphics and machine learning.

### Functions and rates
A function f takes an input x and returns f(x). Its **average rate of change** between x and x + h is the slope of the line joining the two points:

```text
(f(x + h) − f(x)) / h
```

A car that covers 150 km in 2 hours averaged 75 km/h. But what was its speed at one instant? Over zero time it covers zero distance, and 0/0 means nothing.

### Limits
The way out is to ask what the average rate **approaches** as h gets closer and closer to zero without reaching it. That value is a **limit**.

For f(x) = x²:

```text
((x + h)² − x²) / h = (2xh + h²) / h = 2x + h
```

As h shrinks towards 0, this approaches 2x. No division by zero was performed; we simplified first and then asked where the expression was heading.

A function is **continuous** at a point if its limit there equals its value: the graph has no jump or hole.

### The derivative
The **derivative** of f at x is that limit:

```text
f'(x) = lim (h → 0) of (f(x + h) − f(x)) / h
```

It is the **instantaneous rate of change**, and geometrically the **slope of the tangent line** to the graph at x. It is also written df/dx.

So the derivative of x² is 2x. At x = 3 the curve is rising with slope 6; at x = 0 it is flat; at x = −1 it is falling with slope −2.

### The tangent line as an approximation
Near a point x₀, a smooth function is almost a straight line:

```text
f(x) ≈ f(x₀) + f'(x₀) × (x − x₀)
```

This **linear approximation** is why derivatives matter in computing. Newton's method, gradient descent and error estimates all replace a difficult function by its tangent, solve the easy problem, and repeat.

### Reading a derivative
- f' > 0: the function is increasing.
- f' < 0: it is decreasing.
- f' = 0: the tangent is horizontal, a candidate for a maximum or minimum.

The derivative of position is **velocity**. The derivative of velocity is **acceleration**, the **second derivative** of position, written f''. The second derivative tells which way the graph bends: positive means curving upward like a bowl.

### Where it fails
A function has no derivative where its graph has a corner (|x| at 0), a jump, or a vertical tangent. This matters in practice: the popular neural-network function max(0, x) has a corner at 0, where software simply picks a value.

### Units
A derivative has units of output per unit of input: metres per second, dollars per item, errors per parameter. Checking the units catches many mistakes.

> Key idea: The derivative is the limit of average rates of change: the slope of the tangent, and the best straight-line approximation to a function near a point.

* 10
- 25
! f'(x) = 2x, so f'(5) = 10.
#Q What does f'(x) = 0 tell you about the graph at x?
- The function is zero there
* The tangent is horizontal: a possible maximum or minimum
- The function is undefined
! A flat tangent is a candidate turning point.

#LESSON Rules of differentiation and optimisation | 13
Nobody computes derivatives from the limit definition each time. A few rules cover almost every function.

### The basic rules
```text
constant:          (c)' = 0
power:             (xⁿ)' = n·xⁿ⁻¹
constant multiple: (c·f)' = c·f'
sum:               (f + g)' = f' + g'
product:           (f·g)' = f'·g + f·g'
quotient:          (f/g)' = (f'·g − f·g') / g²
```

A polynomial is differentiated term by term:

```text
f(x) = 4x³ − 5x² + 7x − 2        f'(x) = 12x² − 10x + 7
```

Some important derivatives:

```text
(eˣ)' = eˣ          (ln x)' = 1/x
(sin x)' = cos x    (cos x)' = −sin x
```

The exponential function is its own derivative, which is why it describes growth in proportion to size: populations, compound interest, radioactive decay.

### The chain rule
For a function of a function, multiply the rates:

```text
if y = f(g(x))    then    dy/dx = f'(g(x)) × g'(x)
```

Example: y = (3x + 1)². The outer function is squaring, the inner is 3x + 1. So dy/dx = 2(3x + 1) × 3 = 6(3x + 1).

If a change in x changes u three times as fast, and a change in u changes y twice as fast, then y changes six times as fast as x. The chain rule is that statement.

It is the most important rule in computing. A neural network is a long composition of functions, and **backpropagation** is the chain rule applied from the output back to every parameter.

### Finding maxima and minima
At a peak or a valley of a smooth function the tangent is horizontal. To optimise f:

1. Solve f'(x) = 0 to find the **critical points**.
2. Classify each with the second derivative: f'' > 0 is a **minimum** (bowl); f'' < 0 is a **maximum** (dome).
3. Check the ends of the allowed range as well.

Example: a quadratic ax² + bx + c has f'(x) = 2ax + b, which is zero at x = −b/(2a): the **vertex**. It is a minimum if a > 0.

### Local and global
A critical point is a **local** extreme: the best in its neighbourhood. The **global** optimum is the best overall. A function with many valleys has many local minima, and calculus alone does not say which is lowest. **Convex** functions, shaped like a single bowl, have just one, which is why they are prized.

### Gradient descent
When f'(x) = 0 cannot be solved by algebra, walk downhill. The derivative gives the uphill direction, so step the opposite way:

```text
x ← x − rate × f'(x)
```

Repeat until the steps become tiny. The **learning rate** controls the step: too small and progress is slow; too large and the steps overshoot the valley and may diverge. This simple loop, in millions of dimensions, is how machine-learning models are trained.

### Related uses
- **Sensitivity:** how much does the output change if this input is nudged?
- **Error propagation:** an input error δ becomes roughly f'(x) × δ in the output.
- **Marginal cost** in economics is a derivative.

> Key idea: Differentiate with the power, product and chain rules. Optima occur where the derivative is zero, and gradient descent finds them by stepping against the derivative.

- 4x² − 5x + 7
* 12x² − 10x + 7

! Multiply each coefficient by its power and reduce the power by one.

#LESSON Integration | 12
Differentiation finds a rate from a total. **Integration** goes the other way: from a rate to a total.

### Area as accumulation
If a car's speed is constant, distance is speed × time: the area of a rectangle on a speed-time graph. If the speed varies, the distance is still the **area under the curve**.

To find it, slice the interval from a to b into n thin strips, approximate each by a rectangle of width Δx, and add:

```text
area ≈ f(x1)·Δx + f(x2)·Δx + … + f(xn)·Δx
```

As the strips get thinner, this **Riemann sum** approaches a limit, the **definite integral**:

```text
∫ from a to b of f(x) dx
```

The integral sign is a stretched S for "sum". Area below the axis counts as negative.

### Antiderivatives
An **antiderivative** of f is a function F whose derivative is f. Since the derivative of x³ is 3x², an antiderivative of 3x² is x³. So is x³ + 5: constants vanish when differentiated, so antiderivatives are written with an arbitrary constant, x³ + C.

The power rule in reverse:

```text
∫ xⁿ dx = xⁿ⁺¹ / (n + 1) + C        (n ≠ −1)
```

Integrate a polynomial term by term: ∫ (6x² + 4x + 1) dx = 2x³ + 2x² + x + C.

### The fundamental theorem of calculus
The two halves of calculus are inverse operations:

```text
∫ from a to b of f(x) dx = F(b) − F(a)        where F' = f
```

To find the area exactly, find an antiderivative and subtract its values at the two ends. No limit of sums is needed.

Example: the area under 3x² from 0 to 2 is F(2) − F(0) = 8 − 0 = 8.

It works in the other direction too: the rate of change of the accumulated area is the height of the curve.

### What integrals compute
- Distance from velocity, and velocity from acceleration.
- **Average value** of a function: its integral divided by the length of the interval.
- **Probability:** for a continuous random variable, the probability of landing in a range is the area under its density curve there, and the total area is 1.
- **Expected value**, work done by a varying force, volumes, the energy used by a device from its power draw over time.

### When there is no formula
Many ordinary functions, including the bell curve e^(−x²), have no antiderivative that can be written with elementary functions. Then the integral is computed **numerically**, by the trapezoid or Simpson's rule, which is the Riemann sum idea made efficient. Simulations, physics engines and probability calculations all do this.

### Discrete parallels
A programmer already knows the discrete versions. A **difference** between neighbouring array elements is a derivative; a **running total** (prefix sum) is an integral; and the fact that a difference of prefix sums gives a range sum is the fundamental theorem in discrete form.

### Techniques
**Substitution** reverses the chain rule, and **integration by parts** reverses the product rule. Integration by hand is harder than differentiation, and a computer algebra system is the sensible tool for anything elaborate. What matters is knowing what an integral means and when one is needed.

> Key idea: An integral is an accumulated total: the area under a rate. The fundamental theorem evaluates it as the change in an antiderivative.

! An antiderivative is x²; 3² − 0² = 9.

! Differentiation and integration are inverse operations.

#LESSON Series and functions of several variables | 13
### Approximating functions with polynomials
Computers can add and multiply. How, then, do they compute eˣ or sin x? One answer is to approximate the function by a polynomial.

The tangent line matches a function's value and slope at a point. Matching the second derivative as well gives a parabola that also bends correctly, and so on. The **Taylor series** of f about 0 continues without end:

```text
f(x) = f(0) + f'(0)·x + f''(0)·x²/2! + f'''(0)·x³/3! + …
```

For the exponential function, every derivative at 0 equals 1:

```text
eˣ = 1 + x + x²/2! + x³/3! + x⁴/4! + …
```

Also:

```text
sin x = x − x³/3! + x⁵/5! − …        cos x = 1 − x²/2! + x⁴/4! − …
```

Stopping after a few terms gives an approximation that is excellent near 0 and worsens with distance. The first omitted term indicates the size of the error. For small x, sin x ≈ x: a simplification used throughout physics and engineering.

### Convergence
An infinite sum **converges** if its partial sums approach a limit. The geometric series is the essential example:

```text
1 + r + r² + r³ + … = 1 / (1 − r)        when |r| < 1
```

It appears in the analysis of algorithms (the total cost of doubling an array is 1 + 2 + 4 + … + n < 2n), in finance and in probability. The harmonic series 1 + 1/2 + 1/3 + … **diverges**, though its terms shrink to zero; it grows like ln n, which is where the logarithm in the analysis of quicksort comes from.

### Functions of several variables
Real quantities depend on many inputs. The error of a machine-learning model depends on millions of parameters.

A **partial derivative** is the rate of change with respect to one variable while the others are held fixed. For f(x, y) = x² + 3xy:

```text
∂f/∂x = 2x + 3y        ∂f/∂y = 3x
```

### The gradient
Collect the partial derivatives into a vector, the **gradient**:

```text
∇f = (∂f/∂x, ∂f/∂y)
```

The gradient points in the direction of **steepest increase**, and its length is the rate of increase in that direction. On a map of a hill it points straight uphill, at right angles to the contour lines.

### Gradient descent in many dimensions
To minimise f, step against the gradient:

```text
(x, y) ← (x, y) − rate × ∇f(x, y)
```

This is the same loop as in one dimension, with vectors. At a minimum the gradient is the zero vector. In high dimensions there are also **saddle points**, where the gradient is zero but the point is a minimum in some directions and a maximum in others.

### The multivariable chain rule
If z depends on x and y, and each of those depends on t, the rates add along every path:

```text
dz/dt = (∂z/∂x)(dx/dt) + (∂z/∂y)(dy/dt)
```

Backpropagation applies this rule systematically through a network of operations, reusing intermediate results so that all the partial derivatives are obtained in about the time of one evaluation of the function.

### Where calculus appears in computing
- **Machine learning:** training is gradient descent on a loss function.
- **Graphics:** surface normals are gradients; smooth curves are polynomials matched in value and slope.
- **Simulation:** physics is differential equations, integrated step by step.
- **Algorithm analysis:** sums are estimated by integrals.
- **Signal processing and probability:** integrals throughout.

> Key idea: Taylor series approximate functions by polynomials. With several variables, the gradient collects the partial derivatives and points uphill, and stepping against it minimises a function.

#LESSON Differential equations and change over time | 13
### Equations about rates
Many questions in computing are about how something changes: how fast a population of users grows, how quickly a cache entry goes stale, how a cooling processor approaches room temperature. A **differential equation** states a rule for the rate of change, and solving it gives the quantity itself.

The simplest and most important one says the rate of change is proportional to the amount present:

```text
dy/dt = k · y
```

Its solution is exponential:

```text
y(t) = y0 · e^(k t)
```

where y0 is the starting value. You can check it: the derivative of e^(kt) is k·e^(kt), so the rate really is k times the amount.

### Growth and decay
- If **k > 0** the quantity grows exponentially: compound interest, unchecked viral sharing, the number of nodes at each level of a full binary tree.
- If **k < 0** it decays: radioactive material, a discharging capacitor, a moving average that forgets old data.

Decay is often described by a **half-life**, the time for the amount to halve. Setting e^(k t) = 1/2 gives t = ln(2) / |k|, about 0.693 / |k|. Doubling time for growth is the same formula with k positive.

### Newton's law of cooling
An object's temperature T changes at a rate proportional to the difference from its surroundings S:

```text
dT/dt = −k (T − S)
```

The difference decays exponentially, so T approaches S quickly at first and then ever more slowly. Thermal throttling and sensor smoothing follow this shape.

### Limits to growth: the logistic equation
Real growth runs out of room. The logistic equation adds a capacity C:

```text
dy/dt = k · y · (1 − y / C)
```

When y is small it behaves like exponential growth; as y nears C the rate falls to zero. The result is the S-shaped curve seen in product adoption and in the spread of information through a fixed audience.

### When there is no formula
Most differential equations have no neat solution. Programs then **step** through time: knowing y now and the rate dy/dt, estimate y a short time h later as y + h · dy/dt. This is Euler's method, covered with better alternatives in Numerical Methods. Physics engines, epidemic models and circuit simulators all work this way.

> Key idea: A differential equation describes how something changes. dy/dt = ky gives exponential growth or decay; the logistic equation adds a ceiling; when no formula exists, programs step forward in small increments.

#LESSON Probability with calculus | 12
### From counting to continuous values
With a dice you can list every outcome and its probability. A value like a response time, a sensor reading or a person's height can take any value in a range, so the chance of any one exact value is zero. Instead we describe it with a **probability density function** (PDF), f(x).

The probability that the value falls between a and b is the **area under the density curve** between them:

```text
P(a ≤ X ≤ b) = ∫ from a to b of f(x) dx
```

Two rules follow: f(x) is never negative, and the total area under the whole curve is 1.

### The cumulative distribution
The **cumulative distribution function** F(x) gives the probability that the value is at most x: the area from the far left up to x. It rises from 0 to 1, and its derivative is the density. Percentiles come straight from it: the 95th percentile of response time is the x where F(x) = 0.95. Service-level objectives are written in exactly these terms.

### Three distributions you will meet
- **Uniform** on [a, b]: every value equally likely, so f(x) = 1 / (b − a). Random-number generators produce this, and other distributions are built from it.
- **Exponential** with rate λ: f(x) = λ e^(−λx) for x ≥ 0. It models the waiting time between independent random events, such as requests arriving at a server. Its mean is 1/λ.
- **Normal** (Gaussian): the bell curve, set by its mean μ and standard deviation σ. About 68% of values lie within one σ of the mean and about 95% within two. Sums of many small independent effects tend towards it.

### Expected value as an integral
The **expected value** (mean) of a continuous variable is the density-weighted average:

```text
E[X] = ∫ x · f(x) dx
```

For a uniform variable on [0, 10] this gives 5, as you would hope. Variance is computed the same way from (x − mean)².

### Why programmers care
- Performance work talks in percentiles, not averages, because a long tail of slow requests hurts users even when the mean looks fine.
- Machine-learning losses such as cross-entropy and models such as Gaussian processes are built on densities.
- Simulations draw random values from these distributions; Monte Carlo methods (in Numerical Methods) estimate integrals by sampling.

> Key idea: For continuous values, probability is area under a density curve. The cumulative distribution gives percentiles, and expected value is an integral of x weighted by the density.

@solution
function polyEval(p, x) {
  let result = 0;
  for (let i = p.length - 1; i >= 0; i--) {
    result = result * x + p[i];
  }
  return result;
}

function polyDerivative(p) {
  if (p.length <= 1) return [0];
  const out = [];
  for (let i = 1; i < p.length; i++) {
    out.push(i * p[i]);
  }
  return out;
}

function polyIntegral(p) {
  const out = [0];
  for (let i = 0; i < p.length; i++) {
    out.push(p[i] / (i + 1));
  }
  return out;
}

function definiteIntegral(p, a, b) {
  const F = polyIntegral(p);
  return polyEval(F, b) - polyEval(F, a);
}

function tangentLine(p, x0) {
  const slope = polyEval(polyDerivative(p), x0);
  return { slope, intercept: polyEval(p, x0) - slope * x0 };
}

function vertex(a, b, c) {
  const x = (0 - b) / (2 * a);
  return { x, y: a * x * x + b * x + c, kind: a > 0 ? "min" : "max" };
}

function taylorExp(x, terms) {
  let sum = 0, term = 1;
  for (let k = 0; k < terms; k++) {
    sum += term;
    term = term * x / (k + 1);
  }
  return Math.round(sum * 1000000) / 1000000;
}

function gradient(f, x, y, h) {
  const r = (v) => Math.round(v * 10000) / 10000;
  return [r((f(x + h, y) - f(x - h, y)) / (2 * h)), r((f(x, y + h) - f(x, y - h)) / (2 * h))];
}

function descend(df, x0, rate, steps) {
  let x = x0;
  for (let i = 0; i < steps; i++) {
    x = x - rate * df(x);
  }
  return Math.round(x * 1000000) / 1000000;
}

#LESSON Vectors | 12
**Linear algebra** is the mathematics of vectors and the transformations that act on them. It is the language of computer graphics, machine learning, search, data compression and scientific computing: whenever a program handles many numbers at once, linear algebra is underneath.

### What a vector is
A **vector** is an ordered list of numbers. It can be seen in three ways, all useful:

- as an **arrow** with a length and a direction;
- as a **point** in space;
- as a **list of features**: a house described by (area, bedrooms, age) is a vector in three dimensions.

Nothing restricts vectors to two or three dimensions. A 28 × 28 image is a vector with 784 components; a word in a language model is a vector with hundreds or thousands.

### Addition and scaling
```text
(1, 2) + (3, 5) = (4, 7)        add component by component
3 × (1, 2) = (3, 6)             multiply every component
```

Addition places arrows head to tail. Scaling stretches an arrow, and a negative factor reverses it. Every other operation in the subject is built from these two.

A **linear combination** is a sum of scaled vectors: a·u + b·v. The set of all linear combinations of some vectors is their **span**. Two vectors in different directions span a plane.

### Length
The **norm** (length) of a vector comes from Pythagoras:

```text
‖v‖ = √(v1² + v2² + … + vn²)
```

A **unit vector** has length 1. Dividing a vector by its length **normalises** it, keeping only the direction. The **distance** between two points is the norm of their difference.

### The dot product
```text
u · v = u1·v1 + u2·v2 + … + un·vn
```

The result is a single number. It has a geometric meaning:

```text
u · v = ‖u‖ × ‖v‖ × cos θ
```

where θ is the angle between the vectors. So:

- positive: they point broadly the same way;
- **zero: they are perpendicular (orthogonal)**;
- negative: they point broadly opposite ways.

### Cosine similarity
Rearranging gives the cosine of the angle:

```text
cos θ = (u · v) / (‖u‖ × ‖v‖)
```

This measures how alike two directions are, ignoring their lengths: 1 for the same direction, 0 for unrelated, −1 for opposite. Search engines and recommendation systems represent documents, images and users as vectors and rank by cosine similarity. Semantic search with **embeddings** is this formula applied to vectors produced by a neural network.

### Projection
The **projection** of a onto b is the shadow of a along the direction of b:

```text
proj = ((a · b) / (b · b)) × b
```

It splits a into a part along b and a part perpendicular to it. Projection is how a 3D point lands on a 2D screen, and how a best-fitting line is found.

### Linear independence
Vectors are **linearly independent** if none can be written as a combination of the others; each adds a new direction. A set of independent vectors that spans a space is a **basis**, and the number of vectors in a basis is the **dimension**. The usual basis in the plane is (1, 0) and (0, 1), but any two independent vectors serve, and changing basis is a recurring technique.

> Key idea: Vectors are added and scaled. The dot product measures alignment: zero means perpendicular, and dividing by the lengths gives cosine similarity.

#LESSON Matrices and linear transformations | 13
### A matrix is a function
A **matrix** is a rectangular grid of numbers. Its meaning is this: a matrix **transforms vectors**. An m × n matrix takes a vector with n components and returns one with m.

```text
| 2  0 |   | x |   | 2x |
| 0  3 | × | y | = | 3y |          stretches x by 2 and y by 3
```

To multiply a matrix by a vector, take the dot product of **each row** with the vector.

An equivalent and very useful view: the result is a **linear combination of the matrix's columns**, weighted by the components of the vector. The columns show where the basis vectors go: the first column is the image of (1, 0), the second the image of (0, 1). To build the matrix of a transformation, find where it sends the basis vectors and write those down as columns.

### Linear transformations
The transformations matrices perform are exactly the **linear** ones: those that keep the origin fixed and keep straight lines straight and evenly spaced. Formally,

```text
T(u + v) = T(u) + T(v)        T(c·u) = c·T(u)
```

Rotation, scaling, reflection, shear and projection are linear. Translation is not, which is why graphics adds an extra coordinate.

### Matrix multiplication
Applying B and then A is itself a linear transformation, with matrix **AB**. That is what matrix multiplication means: **composition**.

Entry (i, j) of AB is the dot product of row i of A with column j of B. An m × n matrix can multiply an n × p matrix, giving m × p: the inner dimensions must agree.

```text
| 1 2 |   | 5 6 |   | 1·5+2·7  1·6+2·8 |   | 19 22 |
| 3 4 | × | 7 8 | = | 3·5+4·7  3·6+4·8 | = | 43 50 |
```

Properties:

- **Not commutative:** AB and BA are generally different. Rotating then stretching is not stretching then rotating.
- **Associative:** (AB)C = A(BC). A long chain of transformations collapses into one matrix.
- The **identity matrix** I, with ones on the diagonal, changes nothing: AI = IA = A.

### The transpose
The **transpose** Aᵀ swaps rows and columns. A matrix equal to its transpose is **symmetric**; covariance matrices and the matrices of undirected graphs are symmetric. The dot product can be written u · v = uᵀv.

### Matrices as data
A matrix can also simply hold data: a table with a row per example and a column per feature, an image as a grid of brightness values, a graph as an **adjacency matrix** whose entry (i, j) says whether node i is joined to node j. Powers of an adjacency matrix count paths: entry (i, j) of A² is the number of two-step routes from i to j.

### Neural networks
A layer of a neural network computes **y = f(Wx + b)**: multiply the input vector by a weight matrix, add a vector, and apply a simple non-linear function. A whole network is a chain of such layers. Training on a graphics processor is fast because GPUs were built to multiply matrices.

### Cost
Multiplying two n × n matrices in the obvious way takes n³ multiplications. Libraries (BLAS) are tuned to use the processor's cache and vector instructions and can be a hundred times faster than a naive triple loop. Use them.

> Key idea: A matrix is a linear transformation; its columns are the images of the basis vectors. Multiplying matrices composes transformations, and the order matters.

#LESSON Systems of equations, determinants and inverses | 13
### Linear systems as matrix equations
```text
2x +  y = 3
 x + 3y = 5
```

is the single equation **Ax = b**, with A holding the coefficients. There are two ways to picture it. By **rows**, each equation is a line, and the solution is where the lines cross. By **columns**, we seek the combination of the columns of A that produces b.

A system has exactly one solution, none, or infinitely many: lines that cross once, are parallel, or coincide.

### Elimination
**Gaussian elimination** subtracts multiples of rows from other rows until the system is triangular, then solves from the last equation upward. These **row operations** do not change the solutions. It is the general method for solving linear systems and is what software does.

### The determinant
The **determinant** of a square matrix is a single number with a geometric meaning: the factor by which the transformation **scales area** (or volume).

```text
det | a b | = ad − bc
    | c d |
```

- det = 2: areas double.
- det negative: orientation is flipped, as in a mirror.
- **det = 0: space is squashed flat** onto a line or a point. Information is lost and the transformation cannot be undone.

For a 3 × 3 matrix, expand along a row:

```text
det = a(ei − fh) − b(di − fg) + c(dh − eg)      for rows (a b c), (d e f), (g h i)
```

Also det(AB) = det(A) × det(B): scale factors multiply.

### The inverse
The **inverse** A⁻¹ undoes A: A⁻¹A = I. It exists exactly when the determinant is not zero. A matrix without an inverse is **singular**.

```text
inverse of | a b | = (1 / (ad − bc)) × |  d  −b |
           | c d |                     | −c   a |
```

If A is invertible, Ax = b has the unique solution x = A⁻¹b. In computation, solve by elimination and do not form the inverse: it is slower and less accurate.

### Rank
The **rank** of a matrix is the number of linearly independent columns, which always equals the number of independent rows. It is the dimension of the space the transformation's outputs fill.

- Full rank: nothing is squashed, and a square matrix is invertible.
- Lower rank: some columns are combinations of others. The data contains **redundancy**.

The set of vectors that A sends to zero is its **null space**. If it contains more than the zero vector, different inputs give the same output, so A cannot be inverted.

These statements about a square matrix are all equivalent: it is invertible; its determinant is non-zero; it has full rank; its columns are independent; Ax = b has exactly one solution for every b; only the zero vector is sent to zero.

### Least squares
Real data rarely fits exactly. With more equations than unknowns, such as fitting a line through a hundred points, Ax = b has no solution. **Least squares** finds the x that makes Ax as close to b as possible, by projecting b onto the space spanned by the columns of A. It leads to the **normal equations** AᵀAx = Aᵀb. This is linear regression, the foundation of statistical modelling.

### Nearly singular matrices
A determinant close to zero warns of an **ill-conditioned** system, where small errors in the data produce large errors in the solution. In floating-point arithmetic the question is seldom "is it singular?" and usually "how close to singular is it?".

> Key idea: The determinant is the area scale factor of a transformation. A matrix is invertible exactly when its determinant is non-zero, which is when its columns are independent.

! 1 × 4 − 2 × 3 = −2.

- Every system Ax = b has exactly one solution

#LESSON Eigenvalues and applications | 13
### Vectors that keep their direction
A transformation moves most vectors off their own line. A few special ones are only stretched or shrunk:

```text
A v = λ v
```

Such a non-zero v is an **eigenvector** of A, and the factor λ is its **eigenvalue**. Eigenvectors are the natural axes of a transformation, the directions along which it acts as plain scaling.

For the matrix with rows (2, 0) and (0, 3), the vector (1, 0) is an eigenvector with eigenvalue 2 and (0, 1) one with eigenvalue 3. For the matrix with rows (2, 1) and (1, 2), the eigenvectors are (1, 1) with eigenvalue 3 and (1, −1) with eigenvalue 1.

### Finding them
Av = λv means (A − λI)v = 0 for a non-zero v, so A − λI must be singular:

```text
det(A − λI) = 0
```

For a 2 × 2 matrix this is a quadratic in λ. Two checks: the eigenvalues **add up to the trace** (the sum of the diagonal) and **multiply to the determinant**.

For large matrices nobody solves that polynomial. Iterative algorithms are used instead.

### Power iteration
Multiply any starting vector by A again and again, rescaling each time. The component along the eigenvector with the largest eigenvalue grows fastest and comes to dominate, so the vector turns toward that **dominant eigenvector**, and the scaling factor approaches its eigenvalue. The method needs only matrix-vector multiplications, so it works on enormous sparse matrices.

### PageRank
Model the web as a matrix in which entry (i, j) is the probability that a surfer on page j follows a link to page i. The long-run share of time spent on each page is a vector that the matrix leaves unchanged: an eigenvector with eigenvalue 1. Google's original ranking computed it by power iteration over billions of pages.

### Diagonalisation and repeated application
If A has a full set of independent eigenvectors, then in the basis of those eigenvectors it is diagonal: just a scaling along each axis. Powers become easy, since Aᵏ scales each eigen-direction by λᵏ.

This explains long-run behaviour. Repeatedly applying A:

- components with |λ| < 1 die away;
- components with |λ| > 1 grow without bound;
- the largest eigenvalue eventually dominates.

Stability of simulations, convergence of iterative algorithms, and whether gradients explode or vanish in deep networks are all eigenvalue questions.

### Symmetric matrices
A real **symmetric** matrix has real eigenvalues and perpendicular eigenvectors. This well-behaved case covers covariance matrices and many others that arise in practice.

### Principal component analysis
Data with many features usually varies mostly along a few directions. **PCA** finds them: they are the eigenvectors of the data's covariance matrix, and each eigenvalue is the variance along its direction. Keeping only the top few directions compresses the data, removes noise and makes it possible to draw high-dimensional data in two dimensions.

### The singular value decomposition
Every matrix, square or not, factors as A = UΣVᵀ: a rotation, a scaling along perpendicular axes, and another rotation. The scale factors are the **singular values**. Keeping the largest gives the best low-rank approximation of the matrix, which is how images are compressed and recommendation systems fill in missing ratings. The SVD is the most broadly useful decomposition in applied mathematics.

### Where linear algebra appears
- **Graphics:** every transformation, camera and projection.
- **Machine learning:** data are matrices, models are matrix products, embeddings are vectors.
- **Search:** cosine similarity, PageRank.
- **Compression and signals:** SVD, Fourier methods.
- **Science and engineering:** large linear systems.
- **Graphs:** the eigenvalues of a graph's matrix reveal clusters and connectivity.

> Key idea: Eigenvectors are the directions a matrix only stretches, by the eigenvalue. They govern repeated application, and underlie PageRank, PCA and the SVD.

- The inverse of a matrix

#LESSON Vector spaces, bases and orthogonality | 13
### Span and independence
Take some vectors and form every combination a·u + b·v + …. The set of all such combinations is their **span**. Two vectors in the plane that do not lie on the same line span the whole plane; two that do lie on one line span only that line.

Vectors are **linearly independent** if none of them is a combination of the others. Independence means no vector is wasted: each adds a new direction.

### Basis and dimension
A **basis** of a space is a set of independent vectors that spans it. Every vector in the space can then be written in exactly one way as a combination of the basis vectors, and those weights are its **coordinates** in that basis.

The number of vectors in any basis is the same: that number is the **dimension**. The plane has dimension 2, ordinary space 3, and a word embedding of 300 numbers lives in a 300-dimensional space.

The standard basis uses (1, 0) and (0, 1), but nothing forces that choice. A **change of basis** describes the same vector in different coordinates. Graphics engines do this constantly: a point has coordinates relative to a model, a world and a camera.

### Orthogonality
Two vectors are **orthogonal** (perpendicular) when their dot product is zero. A basis whose vectors are mutually orthogonal and of length 1 is **orthonormal**. Orthonormal bases are the most convenient there are: the coordinate of v along a basis vector q is simply the dot product v · q, with no system of equations to solve.

### Projection
The **projection** of v onto a non-zero vector u is the closest point to v on the line through u:

```text
proj_u(v) = ((v · u) / (u · u)) · u
```

What is left over, v − proj_u(v), is orthogonal to u. Projection splits a vector into "the part along u" and "the part that has nothing to do with u". Shadows in graphics, removing a trend from data, and least-squares fitting (next lesson) all use it.

### Building an orthonormal basis
The **Gram–Schmidt process** turns any independent set into an orthonormal one: take each vector in turn, subtract its projections onto the vectors already chosen, and scale what remains to length 1. Numerical libraries use more stable variants of the same idea in the QR decomposition.

> Key idea: A basis is a minimal set of directions that reaches every vector; the dimension is how many it needs. Orthonormal bases make coordinates simple dot products, and projection splits a vector into a part along a direction and a part perpendicular to it.

#LESSON Least squares and fitting data | 13
### More equations than unknowns
Suppose you measure a server's response time at several loads and want a straight line y = m x + c through the points. With two points there is exactly one line. With twenty noisy points no single line passes through them all: the system has more equations than unknowns and no exact solution.

Written as matrices, each point gives one row:

```text
[ x1 1 ]           [ y1 ]
[ x2 1 ]  [ m ]  ≈ [ y2 ]
[ ...  ]  [ c ]    [ ...]
   A        x        b
```

We cannot make Ax equal b, so we make it as close as possible.

### The least-squares idea
The **residual** of each point is the vertical gap between the measured y and the line's prediction. Least squares chooses the line that minimises the **sum of the squared residuals**. Squaring makes every gap count as positive, punishes large misses more than small ones, and leads to a clean formula.

### The normal equations
Geometrically, Ax can only reach vectors in the column space of A. The best choice is the **projection** of b onto that space, which leaves a residual orthogonal to every column. Writing "orthogonal to every column" as a matrix equation gives the **normal equations**:

```text
Aᵀ A x = Aᵀ b
```

For a straight-line fit, AᵀA is just 2 × 2, so the system is tiny however many points there are.

### A worked example
Fit a line to (0, 1), (1, 3) and (2, 4). Then AᵀA has rows (5, 3) and (3, 3), and Aᵀb is (11, 8). Solving gives m = 1.5 and c ≈ 1.17. The line passes near all three points without touching them exactly, and no other straight line has a smaller sum of squared gaps.

### Beyond straight lines
The same method fits any model that is linear in its unknown weights: a parabola (columns x², x, 1), several input features at once (one column per feature), or seasonal patterns. This is **linear regression**, one of the most used tools in data science, and the first model most machine-learning courses teach.

### Cautions
- Least squares is sensitive to **outliers**: one wild point pulls the line hard, because its squared error is large.
- A good fit is not proof of cause; it summarises the data you have.
- Libraries solve the problem with QR or SVD rather than forming AᵀA directly, which can lose precision when columns are nearly dependent.

> Key idea: When a system has no exact solution, least squares finds the x that minimises the sum of squared residuals by solving AᵀAx = Aᵀb. It projects the data onto what the model can express, and it is the basis of linear regression.

function dot(a, b) {
  let s = 0;
  for (let i = 0; i < a.length; i++) {
    s += a[i] * b[i];
  }
  return s;
}

function r6(x) {
  return Math.round(x * 1000000) / 1000000;
}

function norm(a) {
  return r6(Math.sqrt(dot(a, a)));
}

function cosine(a, b) {
  return r6(dot(a, b) / (Math.sqrt(dot(a, a)) * Math.sqrt(dot(b, b))));
}

function project(a, b) {
  const k = dot(a, b) / dot(b, b);
  return b.map((x) => r6(k * x) + 0);
}

function matVec(A, v) {
  return A.map((row) => dot(row, v));
}

function matMul(A, B) {
  const out = [];
  for (let i = 0; i < A.length; i++) {
    const row = [];
    for (let j = 0; j < B[0].length; j++) {
      let s = 0;
      for (let k = 0; k < B.length; k++) {
        s += A[i][k] * B[k][j];
      }
      row.push(s);
    }
    out.push(row);
  }
  return out;
}

function transpose(A) {
  return A[0].map((_, j) => A.map((row) => row[j]));
}

function identity(n) {
  const out = [];
  for (let i = 0; i < n; i++) {
    const row = [];
    for (let j = 0; j < n; j++) {
      row.push(i === j ? 1 : 0);
    }
    out.push(row);
  }
  return out;
}

function det(A) {
  if (A.length === 2) return A[0][0] * A[1][1] - A[0][1] * A[1][0];
  const [a, b, c] = A[0], [d, e, f] = A[1], [g, h, i] = A[2];
  return a * (e * i - f * h) - b * (d * i - f * g) + c * (d * h - e * g);
}

function inverse2(A) {
  const d = det(A);
  if (d === 0) return null;
  return [[A[1][1] / d, (0 - A[0][1]) / d], [(0 - A[1][0]) / d, A[0][0] / d]];
}

function dominantEigenvalue(A, steps) {
  let v = A.map(() => 1), est = 0;
  for (let s = 0; s < steps; s++) {
    const w = matVec(A, v);
    est = w[0];
    for (const x of w) {
      if (Math.abs(x) > Math.abs(est)) { est = x; }
    }
    v = w.map((x) => x / est);
  }
  return Math.round(est * 10000) / 10000;
}
